# 작업 시작

작업을 사람이 고른 모드와 검사대로 진행한다. 단계마다 할 일은 하네스 훅이 알려 준다.
이 문서에는 시작 절차만 있다. 시작한 뒤에는 훅이 넣어 주는 지시(`[하네스]`로 시작)를 따른다.

## 1. 진행 중인 작업 확인

`.harness/state/task.json`을 읽는다.

- `stage`가 `done`이 아니면 진행 중인 작업이다. 같은 내용 그대로 파일을 다시 저장한다. 그러면 지금 단계의 지시가 들어온다. 그 지시를 따라 이어서 한다.
- 파일이 없거나 `stage`가 `done`이면 2로 간다.

## 2. 모드와 검사 고르기

`.harness/checks.json`의 `checks`를 읽는다. 파일이 없으면 고를 검사가 없다.

AskUserQuestion으로 **사용자에게 묻는다.** 모드와 검사는 사용자가 고른다. 작업 크기를 보고 대신 고르지 않는다.

- 모드 (하나만)
  - `plan`: 계획 → 구현 → 검증 → 마무리. 여러 파일·화면을 건드리는 큰 작업
  - `simple`: 구현 → 검증 → 마무리. 문구·한 곳 수정 같은 작은 작업
- 검사 (여러 개, 고르지 않아도 됨): `checks`의 `name`과 `description`으로 선택지를 만든다. 4개가 넘으면 질문을 나눈다.

AskUserQuestion을 쓸 수 없는 세션(`claude -p`, 서브에이전트)에서는 선택지를 글로 보여 주고 답을 기다린다.
사용자가 요청에 모드와 검사를 이미 적었으면 묻지 않고 그대로 쓴다.

## 3. 시작

`.harness/state/task.json`을 쓴다.

```json
{
  "schemaVersion": 1,
  "title": "작업을 한 줄로",
  "mode": "plan",
  "stage": "plan",
  "checks": ["lint", "unit-test"]
}
```

- `stage`는 모드의 첫 단계다. plan 모드는 `plan`, simple 모드는 `implement`.
- `checks`는 사용자가 고른 검사의 `name`이다. 고르지 않았으면 `[]`.
- 저장하면 첫 단계의 지시가 들어온다. 그대로 따른다.

## 이후

- 단계를 마치면 `task.json`의 `stage`만 다음 단계로 바꾼다. 바꾸면 다음 단계의 지시가 들어온다.
- 단계를 건너뛰지 않는다. 마무리 보고를 마치면 `stage`를 `done`으로 바꾼다.
- 고르지 않은 검사를 임의로 더하거나, 고른 검사를 빼지 않는다. 바꿔야 하면 사용자에게 묻는다.
