# 정책·결정 기록

`docs/wiki/`는 코드에 남지 않는 사실과 결정을 모아 두는 곳이다. 에이전트가 작업을 시작할 때 찾아 읽고, 마무리할 때 쓴다.

## 언제 쓰나

- 작업 중에 정했거나 알게 된 것 중, 코드와 커밋만 보고는 "왜"를 알 수 없는 것만 쓴다.
- 비슷한 기록이 이미 있으면 새로 만들지 않고 그 기록을 고친다. 먼저 `scripts/harness/wiki search <단어>`로 찾는다.
- 사용자가 확인하지 않은 추측은 쓰지 않는다. 근거가 없으면 사용자에게 묻는다.

## 두 종류

- `kind: fact` (기술 기록): 라이브러리·플랫폼이 실제로 어떻게 동작하는지. 다른 팀에서도 맞는 사실
- `kind: rule` (결정 기록): 이 서비스·팀이 정한 규칙과 그 이유

## 형식

경로는 `docs/wiki/<주제>/<영문-소문자-하이픈>.md`다. 쓰고 나면 `scripts/harness/wiki check <파일>`로 형식을 검사한다.

```markdown
---
kind: fact
tags: [SwiftUI, 시트]
---

# 한 줄 요약 (무엇이 어떻게 된다)

## 확인된 동작
## 확인 방법
## 함의
## 안 다룬 것
```

```markdown
---
kind: rule
tags: [홈, 노출개수]
---

# 한 줄 요약 (무엇을 어떻게 한다)

## 규칙
## 적용 범위
## 근거
기획서·이슈·Slack 스레드 주소와 날짜. 없으면 누가 언제 정했는지
## 예외
없으면 "없음"
```

## 기록과 다른 요청

결정 기록과 반대로 바꾸는 요청(예: 기록상 정책인 동작을 버그로 고쳐 달라는 요청)을 받으면 바로 고치지 않는다. 기록과 근거를 보여 주고, 정책을 유지할지 바꿀지 사용자에게 묻는다. 바꾸기로 하면 기록도 고친다.
