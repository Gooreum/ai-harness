# 빌드·검증

## 빌드 방법

- 프로젝트가 정한 빌드·테스트 방법(Makefile, 스크립트, 문서화된 명령, MCP 도구)을 먼저 찾아 쓴다. 없을 때만 `xcodebuild`를 직접 구성한다.
- 스킴과 워크스페이스는 추측하지 않고 `xcodebuild -list`로 확인한다.
- 시뮬레이터 이름을 추측하지 않는다. `xcrun simctl list devices available`로 존재하는 기기를 확인한다.
- 빌드 로그는 첫 번째 에러부터 본다. 뒤따르는 에러는 연쇄 결과인 경우가 많다.
- DerivedData 삭제나 clean 빌드는 캐시 문제가 의심될 때만 한다.

## 검증

- 코드를 바꾼 뒤에는 빌드하고, 변경과 관련된 테스트를 실행한다.
- 결과는 실제로 실행한 명령과 그 결과로 보고한다. 실행하지 못한 검증은 못 했다고 밝힌다.
- 빌드·테스트를 통과시키려고 설정을 완화하지 않는다. 경고 억제, strict concurrency 검사 수준 낮추기, 배포 타겟·Swift 버전 변경, 린트 규칙 비활성화가 여기에 해당한다.

## 프로젝트 파일·설정

- `.pbxproj`를 직접 편집하지 않는다. 프로젝트 생성 도구(Tuist, XcodeGen 등)가 있으면 manifest를 수정하고 재생성한다.
- 생성 도구가 없는데 파일 추가·삭제에 `.pbxproj` 변경이 필요하면, 직접 고치지 않고 사용자에게 알린다.
- 서명, 번들 ID, capabilities, entitlements 변경은 사용자 확인 후에 한다. 서명·프로비저닝 오류는 직접 해결하려 하지 않고 보고한다.
