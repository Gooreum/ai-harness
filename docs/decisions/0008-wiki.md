# 0008. 정책·결정 기록은 프로젝트 안 docs/wiki/와 검색 스크립트로 시작한다

- 상태: 채택
- 날짜: 2026-11-03

## 배경

- 발표의 LLM Wiki(슬라이드 41~54)는 AI가 팀 정책을 모르는 문제를 푼다.
  - 정책은 코드에도 커밋에도 남지 않는다. AI는 이유를 못 찾으면 코드만 보고 그럴듯하게 고친다(스크린샷 업로드 막힘을 버그로 보고 푼다).
  - 마무리 단계에 기록하고(config 한 줄 추가), 작업을 시작할 때 찾아 읽는다. 비슷한 기록이 있으면 고친다.
  - 기술 기록(`kind: fact`)과 결정 기록(`kind: rule`) 두 가지다.
  - 팀 라이브러리 저장소와 검색 MCP(`library_search`)를 쓰고, 한 달 검색 2,322 → 열람 540 → 반영 504를 쟀다.
- 로드맵 후보 19는 "처음에는 프로젝트 안 `docs/wiki/`와 grep, 별도 저장소·검색 MCP는 필요해지면"으로 정했다.
- 발표자의 LLM Wiki 저장소는 찾지 못했다(2026-11-03). 발표 슬라이드와 노트를 기준으로 했다.

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 위치 | 프로젝트의 `docs/wiki/<주제>/<이름>.md`, git에 커밋 | 저장소 하나로 시작한다. 여러 저장소가 같은 기록을 써야 할 때 별도 저장소로 옮긴다 |
| 형식 | 머리말 `kind`(fact·rule)·`tags`, 제목 한 줄, 종류별 항목 | 발표의 템플릿과 같다 |
| 찾기 | `scripts/harness/wiki search`(모든 단어 포함, grep) | 검색 MCP 없이 시작한다. 검색 기록을 남겨 나중에 쓰임을 잴 수 있게 한다 |
| 형식 검사 | `scripts/harness/wiki check` | 템플릿이 무너지면 찾기 어렵다. 쓰고 나서 결정적으로 확인한다 |
| 언제 | 프로젝트 `checks.json`의 단계 prompt에 둔다(시작: 찾기, 마무리: 쓰기). 훅 기본 지시는 바꾸지 않는다 | 발표와 같이 단계를 새로 만들지 않고 config 한 줄로 더한다. 기록을 쓰지 않는 프로젝트에는 지시가 들어가지 않는다 |
| 기록과 반대되는 요청 | 바로 고치지 않고 근거와 함께 사용자에게 묻는다(template 규칙·AGENTS.md) | 발표 슬라이드 49의 동작 |

## 결과

- ReadSharp 임시 워크트리에서 같은 QA 티켓("500자에서 번역이 잘린다, 고쳐 달라")을 기록이 있을 때와 없을 때 돌렸다. 기록은 실험용으로만 만들고 커밋하지 않았다.
  - 두 쪽 모두 `wiki search`를 먼저 돌렸고, 코드를 고치지 않고 사용자에게 물었다.
  - 기록이 없는 쪽도 코드 주석과 커밋 메시지로 의도된 제한이라고 판단했다. 이유는 "안정성" 주석에서 짐작했다.
  - 기록이 있는 쪽은 결정 날짜와 이유(저사양 기기 멈춤)를 근거로 들고, 바꾸면 기록도 고치겠다고 했다.
  - 발표처럼 판단이 정반대로 갈리지는 않았다. 이 코드는 주석과 안내 문구로 의도가 드러나 있었다. 코드에 이유가 없는 결정에서 다시 확인한다.
- 열람·반영 횟수는 재지 않는다. 필요해지면 검색 로그와 세션 기록으로 잰다.

## 추가 (2026-11-09): 위키 지시를 setup이 추천하고 doctor가 확인한다

- 관찰: PetCycle은 setup으로 검사만 정하고 `stages`를 두지 않아 위키 지시가 한 번도 들어가지 않았다. 11-06 이후 커밋 65개 동안 기록이 0개였다. 지시가 있는 ReadSharp(24개)·IntervalTimer(14개)에서는 찾기·쓰기를 빠뜨린 일이 관찰되지 않았다.
- 원인: 위키 지시가 프로젝트 설정에만 있고, setup이 묻지 않았고, doctor도 보지 않았다.
- 결정: 추천 문장을 `common-checks.json`의 `stages`에 두고 setup이 둘지 묻는다(추천). doctor는 `stages`에 위키 지시가 없으면 주의를 준다. 쓰지 않을 프로젝트는 `"wiki": false`로 끈다. 훅 기본 지시는 그대로 둔다(위의 "언제" 결정 유지).
- 하지 않은 것: 위키를 찾았는지·썼는지를 Stop 훅으로 확인하는 것. 발표도 config 한 줄이고 ai-bouncer에는 위키가 없다. 쓰기 강제는 기록할 것이 없는 작업에서 억지 기록을 만든다. 지시가 있는데 빠뜨린 일이 관찰되면 다시 정한다.
