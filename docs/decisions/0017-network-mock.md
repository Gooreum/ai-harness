# 0017. 서버 응답 조작은 실제 서버를 대신하는 가짜 응답 MCP로 한다

- 상태: 채택 (2026-11-05)
- 관련: ADR 0009(E2E Maestro), ADR 0010(행동 로그), 로드맵 후보 10, `plugin/mcp/network.py`, `docs/plugin.md`

## 배경

- 발표 슬라이드 85 "활용 1 · 피처 개발": 500 에러, 느린 네트워크, 빈 응답은 실제 서버로 만들기 어렵다.
  - AI에게 맡겼더니 목 데이터를 40~50개까지 쌓았다. 그래서 팀이 프록시 MCP를 직접 만들었다.
  - AI가 이 MCP로 서버 응답을 원하는 상황으로 바꾸고, 시나리오와 함께 돌린다.
- 발표는 MCP를 어떻게 짰는지 말하지 않는다. ai-bouncer에도 관련 코드가 없다.
- iOS 시뮬레이터에는 기기별 프록시 설정이 없다. 앱 요청을 일반 프록시로 가로채려면 Mac 전체 프록시 설정과 인증서 설치가 필요하다(ADR 0010에서 미룬 이유).
- 사용자 결정(2026-11-05):
  - 목 데이터를 없애는 것이 아니라 프로젝트 코드에서 MCP로 옮긴다.
  - MCP 서버가 실제 서버 대신 직접 응답한다. 시뮬레이터와 Mac 설정은 건드리지 않는다.
  - 하네스에는 어느 프로젝트에나 쓰이는 이 서버만 넣는다. 프로젝트 고유의 MCP는 쓰는 사람이 만든다.

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 구조 | MCP 서버 한 프로세스가 AI의 도구 호출(stdio)을 받고, `127.0.0.1:<포트>`에서 앱 요청에 응답한다. 실제 서버로 넘기지 않는다 | 넘기지 않으니 HTTPS 중계·인증서·Mac 설정이 필요 없다. AI가 응답을 걸면 바로 앱에 반영된다 |
| 앱 쪽 | 실행 인자 `-HarnessNetworkBaseURL`이 있고 값이 `http://127.0.0.1:`로 시작하면 `https://<호스트>/<경로>`를 `<주소>/<호스트>/<경로>`로 보낸다. 각 앱이 직접 넣는다 | API 주소를 읽는 곳이 앱마다 다르다. 인자가 없으면 지금과 같다. 디버그 빌드로 한정하지 않는다: E2E는 스킴의 실행 구성으로 빌드하는데 ReadSharp는 Release다. 사용자는 실행 인자를 넣을 수 없고, 넣어도 자기 기기(127.0.0.1)로만 간다 |
| 도구 | `mock_set`(match·status·delay·body·headers), `mock_list`, `mock_clear`, `requests` | `requests`로 앱이 실제로 보낸 주소를 보고 고르게 해서 추측을 막는다 |
| 켜기 | `project.json`의 `e2e.network.port`가 있을 때만 도구를 내놓고 HTTP 서버를 띄운다 | 플러그인은 모든 하네스 프로젝트에서 켜진다. 서버를 쓰지 않는 프로젝트(IntervalTimer)는 도구 설명이 컨텍스트에 들어가지 않는다 |
| 독립성 | 응답과 요청 기록은 그 프로젝트의 `.harness/state/`에, 포트는 프로젝트마다 다르게. HTTP 서버는 요청마다 파일을 읽는다 | 프로젝트끼리 섞이지 않는다. 같은 프로젝트를 두 세션이 열어도 같은 응답을 준다 |
| 언어 | python3 표준 라이브러리 | 원칙은 bash+jq이지만 bash로는 HTTP 서버를 짤 수 없다. python3는 Xcode 명령줄 도구에 들어 있어 따로 설치하지 않는다 |
| e2e | `e2e.network.port`가 있으면 maestro에 `NETWORK_BASE_URL`을 넘기고, 서버가 떠 있지 않으면 알린다 | 시나리오가 `launchApp.arguments`로 앱에 준다 |
| 판정 | 시나리오 옆 `<이름>.network.json`의 `expect`(match·status)가 그 흐름 동안 서버 기록에 있어야 통과 | 응답을 걸지 않았거나 서버가 꺼져도 앱의 실패 화면은 똑같이 뜬다. 화면만 보면 헛통과한다(시험장에서 확인, 2026-11-05). 행동 로그(ADR 0010)처럼 흐름 구간으로 나눈다 |

## 결과

- 응답 조건은 MCP 세션 동안만 있다(파일에 남지만 서버는 Claude Code 세션이 띄운다). AI 없이 돌리는 회귀 묶음에서는 이 조건을 재현하지 않는다. 응답이 없으면 `network.json` 판정으로 실패해, 헛통과하지 않는다.
- 가짜 응답 본문은 AI가 MCP에 넘긴다. 프로젝트 코드에 목 파일이 생기지 않는다.
- 앱 코드에 디버그 전용 몇 줄이 들어간다. 하네스는 대신 넣을 수 없다.
