# 0029. PR을 만들 때 이번 작업에서 찍은 영상을 본문에 넣는다

- 상태: 채택 (2026-11-10)
- 관련: ADR 0009(E2E와 `--record`), ADR 0024(플랫폼 도구는 프로젝트가 갖는다), ADR 0028(마무리 단계는 PR을 만들지 않는다), `template/scripts/harness/pr-video`, `template/AGENTS.md`

## 배경

- 발표 슬라이드 87: QA 티켓을 고칠 때 만든 시나리오로 수정 전후 영상(`before.mp4`, `after.mp4`)을 남긴다. 이 영상을 MR에 함께 올리므로, 리뷰어는 앱을 실행하지 않고 결과를 본다. 어떻게 올리는지는 발표에 없다.
- ai-bouncer에는 영상이나 PR을 다루는 코드가 없다.
- 지금까지는 e2e 검사가 `--record`로 `.harness/out/e2e.mp4`를 남기기만 했다. PR에 넣는 일은 아무도 하지 않았다.
- 사용자 결정(2026-11-10): "영상 촬영된건 PR 할때 같이 올리게 해줘", "무조건이 아니라 영상 촬영한게 있으면 올리게". 다운로드하지 않고 PR에서 바로 보이게 한다.
- 조사한 것
  - GitHub PR 본문에서 영상 플레이어로 보이는 것은 웹에서 올린 첨부(`https://github.com/user-attachments/assets/…`)뿐이다. `gh`나 공개 API로는 올릴 수 없다. 저장소에 올린 mp4는 링크로만 보인다.
  - Chrome(claude-in-chrome)으로 PR 본문 편집 칸에 파일을 첨부하면 그 칸에 첨부 링크가 들어가고, 저장하면 본문에서 영상으로 재생된다.
  - 하네스를 설치한 ReadSharp와 IntervalTimer 저장소는 둘 다 무료 요금제라 영상 한 개가 10MB까지다. ReadSharp의 76초 녹화는 24.8MB, HEVC다.
  - macOS 기본 도구 `avconvert`로 바꾸면 960×540 프리셋이 9.0MB, 640×480이 5.8MB였고 둘 다 H.264다.

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 언제 | PR을 만들 때만. 영상이 없으면 아무것도 하지 않는다 | 사용자 결정. 마무리 단계는 PR을 만들지 않는다(ADR 0028) |
| 고르는 영상 | `.harness/out/*.mp4` 중 `task.started` 뒤에 생긴 것. `<이름>-before.mp4`는 수정 전 | 지난 작업의 영상이 섞이지 않게 `passed`와 같은 기준을 쓴다. 영상은 프로젝트의 e2e가 남기므로(ADR 0024) 하네스는 파일 이름만 정한다 |
| 크기와 형식 | `avconvert`로 H.264 960×540, 9.5MB 이상이면 640×480, 그래도 크면 같은 길이로 나눈다. 9.5MB는 무료 요금제 한도 10MB에 여유를 둔 값이다 | macOS 기본 도구만 쓴다. HEVC는 Chrome에서 재생되지 않을 수 있다 |
| 올리기 | 에이전트가 Chrome으로 PR 본문을 편집해 `## 영상` 절에 제목을 쓰고 파일을 첨부한 뒤 저장한다. 저장 뒤 `gh pr view`로 확인한다 | 본문에서 재생되는 유일한 방법이다. 처음에는 댓글 칸에 첨부해 링크만 받고 `gh pr edit`로 넣었으나, 사용자가 본문에 바로 넣으라고 했다(2026-11-10). 스크립트로는 할 수 없어 AGENTS.md 지시로 둔다 |
| 브라우저를 못 쓰면 | 파일 경로를 보고에 적고 사용자에게 끌어다 놓아 달라고 한다 | 영상은 리뷰를 돕는 것이라, 영상을 못 올려도 PR을 막지 않는다 |

## 발표·ai-bouncer와 다른 점

- 영상을 PR에 함께 올리는 것은 발표와 같다. 올리는 방법은 발표와 ai-bouncer에 없어 새로 정했다.
- 훅으로 확인하지 않는다. 영상을 빠뜨린 일이 아직 관찰되지 않았다(원칙: 강제 장치는 실패가 관찰된 뒤에 넣는다).

## 결과

- 영상을 찍은 작업의 PR에는 그 영상이 본문에서 재생된다.
- 수정 전 영상은 프로젝트의 e2e 검사가 `e2e-before.mp4`로 옮겨 둔 경우에만 함께 들어간다. ReadSharp의 `scripts/ios/e2e --record`는 늘 `e2e.mp4`에 덮어쓰기 때문이다. 시험장 ReadSharp의 e2e 검사 prompt에 이 지시를 넣었다.
- 첨부하려면 Chrome이 GitHub에 로그인돼 있고 Chrome 확장이 연결돼 있어야 한다. 둘 중 하나라도 안 되면 사람이 올린다.
