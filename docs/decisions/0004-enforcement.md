# 0004. 처음 넣는 강제 장치는 훅 하나와 권한 규칙으로 나눈다

- 상태: 채택
- 날짜: 2026-10-12

## 배경

- 원칙상 강제 장치는 처음에는 위험하거나 되돌리기 어려운 행동을 막는 것만 넣는다. 대상은 세 가지다.
  - 자동 생성 파일과 `project.pbxproj` 편집
  - 서명·시크릿 파일 읽기
  - 파괴적이거나 외부에 공개되는 git 작업
- Claude Code에는 강제 수단이 두 가지 있다.
  - **PreToolUse 훅**: 스크립트가 도구 호출을 보고 막는다. 막는 이유를 에이전트에게 직접 전할 수 있다.
  - **권한 규칙**(`deny`, `ask`): 설정 파일에 경로·명령 패턴을 적는다.
    - Read·Edit 규칙은 파일 도구뿐 아니라 Bash의 `cat`·`sed`·`tee`와 리다이렉션에도 적용된다.
    - `ask`는 auto 모드에서도 사용자에게 확인을 묻고, 확인할 사람이 없는 모드(dontAsk)에서는 거부된다.
- 둘 다 완전한 보안 경계는 아니다. Bash 규칙은 `git -C . push`처럼 다르게 쓴 명령은 잡지 못한다. 여기서는 실수를 막는 것이 목적이다.

## 결정

| 대상 | 수단 | 이유 |
|---|---|---|
| 자동 생성 파일(Tuist·XcodeGen의 `*.xcodeproj/`, `*.xcworkspace/`, `Derived/`) | 플러그인 훅 `protect-generated.sh` | 생성기를 알아야 판단할 수 있고(설정 파일), "manifest를 고치라"는 안내를 줄 수 있다 |
| `project.pbxproj` | 같은 훅 + `Edit(**/*.pbxproj)` deny | 훅이 안내를 주고, 권한 규칙이 Bash로 우회하는 편집까지 막는다 |
| 서명·시크릿 파일(`*.p12`, `*.p8`, `*.mobileprovision`, `.env`, `.env.*`) | `Read` deny | 코딩에 필요 없다. Read deny는 같은 경로의 편집도 막는다 |
| 파괴적 git 명령, 외부 공개 작업(push, PR 생성·머지) | ~~`ask` (`git -C <경로>` 형식 포함)~~ → ADR 0026에서 뺐다. 지침과 auto 모드 분류기에 맡긴다 | 사용자가 실제로 요청했을 때는 확인 후 실행할 수 있어야 한다. "요청할 때만 쓴다"는 지침과 맞다 |

- 훅은 판단할 수 없으면 막지 않는다(fail-open). 설정 파일이 없거나 입력 JSON이 깨진 경우다. 고장 난 훅이 정상 작업을 막지 않게 하기 위해서다.
- 훅은 stdin JSON만 읽는다. Codex의 편집 입력(apply_patch) 처리는 Codex 어댑터(후보 16)에서 추가한다.
- 권한 규칙은 `template/.claude/settings.json`에 두고 프로젝트에 설치한다. 프로젝트에 설정 파일이 이미 있으면 설치 도구가 합친다(단위 9).
- 커밋 자체는 로컬에서 되돌릴 수 있어서 강제하지 않는다. 커밋 전 확인은 지침(AGENTS.md)으로만 둔다.

## 결과

- 좋아지는 점
  - 에이전트가 생성 파일을 고치려 하면 막히면서 manifest를 고치라는 안내를 받는다.
  - 시크릿 파일은 내용이 컨텍스트에 들어오지 않는다.
  - 파괴적 명령은 사용자 확인 없이 실행되지 않는다.
- 비용
  - `git restore --staged`처럼 해가 없는 명령도 `ask`에 걸려 확인을 묻는다.
  - 불편이 관찰되면 규칙을 좁힌다.
- 확인 방법
  - 훅: 회귀 테스트 14개와 MotoTrace 실제 경로로 판단을 확인했다(생성 파일 3종 차단, 소스·manifest 허용).
  - 플러그인·마켓플레이스: `claude plugin validate`를 통과했다.
  - 실제 Claude Code 세션(MotoTrace에서 띄운 터미널 `claude -p`)에서 다음을 확인했다.
    - 플러그인이 하네스 저장소의 `plugin/`에서 바로 로드됐다.
    - 편집 자동 허용 모드에서도 생성 파일 편집이 훅에 막혀 안내 문구가 전달됐다. 파일은 바뀌지 않았다.
    - `Certificate/dev.p12` 읽기가 권한 규칙에 막혔다.
    - `git` 명령 전체를 허용한 상태에서도 `git reset --hard`(와 `git -C <경로>` 형식)가 확인 요청으로 막혔다. 같은 허용 설정에서 ask 목록에 없는 `git update-index`는 실행됐다.
