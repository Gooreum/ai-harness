# 0003. 프로젝트 AGENTS.md를 프로젝트 영역과 하네스 관리 블록으로 나눈다

- 상태: 채택
- 날짜: 2026-10-12

## 배경

- 프로젝트에 설치된 AGENTS.md에는 두 종류의 내용이 섞인다.
  - 모든 프로젝트에 공통인 하네스 내용: 빌드·테스트 명령, 꼭 지킬 규칙, 규칙 목록
  - 프로젝트에만 있는 내용: 앱 소개, 구조, 고유 규칙
- 하네스를 갱신할 때 공통 부분은 바꾸고, 프로젝트 부분은 보존해야 한다.
- 로드맵에는 "설정 파일에서 명령 블록을 생성한다"고 적었다. 하지만 build·test·verify가 `.harness/project.json`을 직접 읽기 때문에 명령은 모든 프로젝트에서 같다.

## 결정

1. **AGENTS.md를 두 영역으로 나눈다.**
   - 위쪽은 프로젝트 영역이다.
   - 아래쪽은 `<!-- harness:begin -->`부터 `<!-- harness:end -->`까지의 하네스 관리 블록이다.
   - 갱신 도구는 관리 블록만 바꾼다.
2. **두 영역이 충돌하면 프로젝트 규칙을 따른다.** 이 문장을 관리 블록 안에 둔다. 그래서 프로젝트는 관리 블록을 고치지 않고도 기본 규칙을 바꿀 수 있다.
3. **명령 블록은 생성하지 않고 고정 문장으로 둔다.** 프로젝트별 값은 설정 파일에만 둔다.
4. **CLAUDE.md는 `@AGENTS.md` import 한 줄로 둔다.** Claude에만 해당하는 지침이 생기면 그 아래에 덧붙인다.
5. **프로젝트 고유 경로 규칙은 `.claude/rules/project/`에 둔다.** 하네스가 관리하는 `.claude/rules/harness/`와 섞이지 않게 한다.

## 결과

- 좋아지는 점
  - 템플릿을 고친 뒤 프로젝트에 반영할 때 갱신 범위가 분명하다.
  - 생성 단계가 없어서 설치가 단순하다.
- 비용
  - 관리 블록을 프로젝트에서 직접 고치면 갱신할 때 덮어써진다. 블록 위의 HTML 주석으로 알린다.
  - 갱신 도구(후보 14)는 관리 블록이 바뀌었으면 경고해야 한다.
- 확인 방법
  - 이 저장소 안의 임시 프로젝트에 CLAUDE.md와 AGENTS.md를 두고 그 안의 파일을 읽어 확인했다.
  - CLAUDE.md의 import가 펼쳐져 AGENTS.md 내용이 로드됐다.
  - HTML 주석(안내 문구, 블록 표시)은 컨텍스트에서 빠졌다.
